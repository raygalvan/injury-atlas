# Private UI presentation

The experimental `injury.bot.afp/0.1` manifest now includes `application-presentation`, contract `injury.bot.application.presentation/0.1`, feature `private-application-presentation`, permission `ui.presentation.private.write`.

One `ui-editing` permission covers all discovered host presentation surfaces. Standard and Lab permit it automatically; an explicit Blocked or global Protected policy is still enforced. The Coordinator does not need another approval for each button, property or screen. This permission does not supply arbitrary executable code.

`inspect_private_afp_ui` searches static source labels/classes and returns target IDs, current private edits and browser-reported computed presentation. `edit_private_afp_ui` sets typed styles/static labels, undoes the most recent change, disables or removes an override. Both text and voice use the same authenticated SDK. Neither accepts identity, selectors, arbitrary CSS, URLs, code or settings access. Case content and form values are never part of the inventory. Dimensions are numeric pixels, colors validated hexadecimal values, and layout properties enumerated. Viewports may be all, mobile or desktop. Repeated instances from the same source surface share its presentation override, not its data.

The build-time TypeScript transform instruments source surfaces and generates `shared/afp-ui-catalog.json`. This is not a list of separately authorized controls. Stable IDs derive from file/tag/static presentation signature and duplicate ordinal, not source line numbers. Changed signatures produce new IDs; unmatched old edits remain retained but do not attach to a different target. Login and the recovery editor are excluded. Embedded Atlas content remains behind its existing engine bridge; this host adapter does not edit iframe DOM. Creating new behavior/components remains outside this declarative presentation contract.

Persistent SQLite tables `afp_ui_edits`, `afp_ui_history`, and `afp_ui_observations` are added automatically. Rows are keyed to authenticated user and current firm. Manifest, integrity, current policy and optimistic revision checks apply. No private source files or shared deployment are generated. Audit stores validated presentation changes, actor, scope, source, timestamp and result, not conversation transcripts. Product-context export includes aggregate counts only. Disable/remove restores base presentation; history is retained. The recovery editor is Settings → AFP Management → AFP Features → My private UI edits.

The browser adapter loads only the current account's compatible configuration, reapplies after navigation, polls for text/voice edits, and removes styling on logout. A saved edit returns pending observation, not a claim of visual success. The Coordinator can inspect browser-reported styles, revision and viewport after the target is opened. These are client observations, not independent screenshot attestation. Offscreen targets apply on opening. Tests use synthetic accounts and providers, never real evidence, email or keys.

The development journal, proposal lifecycle and protected core remain intact. Live proposals were unavailable in the development workspace; no proposal was marked reviewed or verified by this change.
